# Changelog

All notable public changes to TokenBar are documented here.

## Unreleased

- **A finished Alibaba Cloud sign-in could leave the loopback port bound forever.** The listener's descriptor was closed from the `DispatchSource` cancel handler, which runs on a later queue turn and reached it through `weak self` — so whenever the server deallocated first (the normal case: `run()` returns as soon as the token lands, and the success/timeout paths drop it immediately), the handler found no object, skipped the close, and left a socket in `LISTEN` with nothing servicing it. Observed on a long-lived instance: a port still bound seven hours after the sign-in, accepting TCP connections that were never answered. The handler now captures the descriptor **by value**, so closing cannot depend on the object's lifetime, and the idempotence flag that only existed to guard the two close paths is gone (they are mutually exclusive by construction). Four tests now assert the port is free after success, cancellation, timeout, and a bind that never served.
- **Fixed the Alibaba Cloud Token Plan tab reporting "no active subscription" for accounts that have one.** The real console response for a personal **Essential** plan is `{"per1MonthPercentage":0.0143…,"per1MonthResetTime":1792857600000}` — a **monthly** window only. TokenBar read only the two ratios the official CLI prints (`per5HourPercentage`, `per1WeekPercentage`), found neither, and concluded the account held no plan at all; the CLI itself prints "the 5-hour limit may be unlimited" for the same account, so copying it was not enough. `parseTokenPlan` now reads the 5-hour, weekly **and** monthly ratios, and a plan that publishes only the monthly one renders one ring instead of erroring. Regression-tested against the captured payload.
- **The Alibaba Cloud Token Plan card now carries its expiry date and plan tier.** The usage API publishes no dates, so the provider now also reads the subscription record the console page requests next to it — `zeldaHttp.apikeyMgr./tokenplan/personal/api/v2/subscription` → `specCode` (`"essential"` → the `Essential` edition) and `endTime` (the expiry badge and the countdown, and what feeds the expiry reminders). A subscription failure costs those two extras and is written to the diagnostic instead of failing a refresh that already has usage. `remainingDays` is deliberately ignored: the app derives the countdown from the date, and a cached copy would drift.
- **The Bailian console page no longer hangs on 「授权中」 after a successful sign-in.** Every callback answer now carries `Access-Control-Allow-Origin: *` (the official CLI sends it on its `OK` response too). The console posts the token with a cross-origin `fetch`, so a 200 without that header is a failure *as far as the page is concerned* — the token had already landed, the Keychain had been written, and the user just watched a spinner. Clicking again then stacked another loopback listener for the remainder of its ten-minute timeout; a new sign-in attempt now cancels the previous one (the cancelled task releases its port immediately and reports nothing, so a superseded click is not logged as a failure).
- Two more Alibaba Cloud console-gateway divergences from the live response: the error detail is read from `errorMsg` as well as `errorMessage` (the observed `BailianGateway.Login.NotLogined` envelope uses `errorMsg`, so the detail was being dropped), and when both plan APIs answer but neither has data, `aliyun-last-response.txt` now records **both raw payloads** — "no such plan" and "the payload moved" were otherwise indistinguishable from the menu.
- Two Alibaba Cloud tests stopped destroying the developer's own sign-in: `browserTokenUsed` and `expiredBrowserTokenFallsBack` wrote a fake console token into the shared `AppSettings` and cleared it unconditionally on the way out, so running the suite while actually signed in logged the machine out — and a real sign-in landing mid-run made the mocked flow tests read a live token. Both now save and restore the previous value.
- **The Alibaba Cloud browser sign-in can now actually start.** The callback listener used `NWListener`, and on a Mac with an active VPN network extension every bind fails with `NWError … 22 (EINVAL)` — not just the current parameter set: a fixed port, `requiredInterfaceType = .loopback`, `acceptLocalOnly` and even UDP all failed the same way in a minimal repro, while a plain socket on `127.0.0.1` bound and answered a full HTTP round trip. The result was that "浏览器登录百炼控制台" could never get past *listener failed* on such a machine, so the token-callback path — and with it the whole tab — was unreachable for anyone who signs in with a WireGuard/TUN VPN running. The callback server is now a loopback-only BSD socket driven by a `DispatchSource` read handler, which is also closer to the official CLI's `listenLocalServer` (it binds `127.0.0.1` exclusively, where `NWListener` would have listened on **every** interface). Cancelling is what releases the descriptor when a login was running, and `stop()` closes it directly when the listener was bound but never served (a login that bailed before starting) — one idempotent path each, so neither can leak a bound port. The old code also started the same listener twice (`readyPort` started it, then `run` started it again), which is an invalid transition on its own; that path is gone.
- **Alibaba Cloud's console gateway calls match the official CLI on three more points.** Every call now carries the `cornerstoneParam` routing block: the CLI's `buildGatewayParams()` injects it into `Data` for **all** APIs, while TokenBar only attached it to the Coding Plan call, leaving the Token Plan call with an empty `Data`. A callback that arrives with the correct `state` but no token no longer aborts the sign-in — the console posts intermediate requests, and the CLI answers them and keeps waiting, so this now does the same and only ends on the token or the 10-minute timeout (the `aliyunConsoleLoginState` / `aliyunConsoleLoginNoToken` messages became unreachable and are removed). And `multipart/form-data` callback bodies are parsed: the documented behavior claimed it and the CLI handles it (`parseAccessTokenFromMultipart`, for a `fetch()` with a `FormData` body), but no such branch existed — a `FormData` post would have produced "no token" instead of a login. Request parsing also stopped reconstructing the body by splitting and re-joining lines, which is now a byte-exact slice at the header terminator.
- Alibaba Cloud tests grew from 31 to 43. Six are the first **socket-level** tests for the sign-in — a real loopback connection delivers the token to `serve()`, a tokenless and a forged-state callback both keep the login waiting, a posted form body arrives, a console that never calls back times out, a listener bound but never served still releases its port, and a cancelled attempt releases its port too — one pins the CORS header the console page needs, four assert the gateway request body and error envelope (both plans carry `cornerstoneParam`; the Token Plan `Data` holds nothing else; the Coding Plan query survives; `errorMsg` reaches the user), and one parses a monthly-only Token Plan from the captured live payload. The suite now stands at 231 tests in 57 suites (43 of them Alibaba Cloud).
- **Alibaba Cloud (阿里云百炼) Coding Plan / Token Plan usage now works for real.** The tab shipped as a stage-1 skeleton that always reported "not activated yet" because Alibaba publishes no usage API; the plan was to capture the console request after activation. The contract is now confirmed from the official open-source CLI (`github.com/modelstudioai/cli`, `bl usage token-plan` / `bl usage coding-plan`) instead of guesswork, and the provider follows it exactly — including the CLI's own **browser login**: "浏览器登录百炼控制台" opens the console login page and receives the console access token on a loopback callback, the identical mechanism as `bl auth login --console`, so **no AK/SK is needed**. Three credential paths are supported, in priority order: the browser-login token (Keychain), an AK/SK mint (ACS3-HMAC-SHA256-signed `GenerateCLIAccessToken`, cached in memory ~10 minutes and re-minted on 401 — including the gateway's HTTP-200 `success: false` error envelopes), and the `sk-sp-` plan key as a last-resort Bearer attempt on the console gateway (a rejected key costs no quota — it is a metadata API, not a model call). An account holds either a **Token Plan** (credit ratios: 5-hour + weekly rings) or a **Coding Plan** (request counts: 5-hour 6,000 / weekly 45,000 / monthly 90,000 rings); the provider detects which one on the first successful fetch, remembers it as a plain preference, and later refreshes query only that product's API — one usage read per refresh, no probing. An expired browser token falls back to AK/SK when configured, otherwise reports `aliyunConsoleLoginExpired`; a rejected AK/SK reports `aliyunInvalidToken` with a permission hint; failures write a redacted diagnostic to `aliyun-last-response.txt`. The settings pane and console button are renamed from the Coding-Plan-only wording to the product-neutral "阿里云百炼 / Alibaba Cloud Bailian", and the console button opens the console root instead of the Coding Plan page. Contract and rationale are recorded in docs/aliyun-handoff.md.
- The Ark API-key probe no longer bills on every refresh. It probed `POST /api/coding/v3/chat/completions` with `max_tokens: 1` — up to four real billed requests per refresh (environment `ARK_MODEL_ID` plus three hard-coded fallbacks), and in `.auto` mode it ran *before* the free arkcli path, so anyone who exported `ARK_API_KEY` silently paid per-request quota for numbers they used to get for free. A zero-cost `GET /api/coding/v3/models` probe now runs first (the gateway attaches the same `x-ratelimit-*` headers to it), and the billed chat probe only runs when that route is missing or carries no quota contract — then exactly once, with no model fan-out. A 429 from either probe still counts as success (the rate-limit headers are the point).
- Fixed Kimi showing a different account's quota after a re-import. Importing a new access token without a refresh token left the previous account's refresh token in place, and on the next 401 that stale refresh minted the *old* account's access token and overwrote the freshly imported one — the tab silently displayed another account. Access and refresh tokens are now paired by their JWT `sub` claim in every resolution branch (a provably mismatched pair is dropped, and a fresh import that finds no refresh token clears a cached one from another account), and the refresh fallback in `KimiProvider` applies the same check.
- LongCat's Cookie source selector now works. The picker was persisted and even triggered a refresh on change, but `LongCatProvider` always resolved manual → cached browser session → environment, so switching back to Automatic kept using the stale manual cookie until it expired. Resolution now follows the selection: Manual uses only the pasted cookie (normalized), Automatic uses the browser session and falls back to `LONGCAT_MANUAL_COOKIE` — the same semantics as the OpenCode Go selector.
- Error response bodies are truncated before they reach the UI or stderr. Five providers interpolated the raw body into `UsageError.apiError`, so a chatty 5xx HTML page could put megabytes of text into the menu and the log — contradicting the documented "credentials never in logs" promise. A shared `HTTPErrorSummary` now keeps structured `Code`/`Message` fields and flattens everything else to a bounded single line (300 characters); the per-provider `errorSummary` copies are gone.
- The Overview now follows the same binding-constraint rule as the menu bar. Its rows read `sessionWindow`, so a provider whose weekly pool was exhausted showed a full "100%" row while the menu bar honestly showed 0%. Rows, the status-item icon, and the summary refresh row all consume one shared `UsageStore.tightestVisibleTab` / `menuBarWindow` pick, so the icon, the row and the refresh state can no longer come from three different providers.
- The Keychain prompt names the provider you actually imported. SweetCookieKit's handler is a global singleton registered by the OpenCode module, so every provider's import showed "…to decrypt the opencode.ai sign-in Cookie" — a false statement for the five other providers that use the same handler, several of which forward all cookies rather than "only the authentication cookie". The prompt now carries the importing provider's name, drops the false promise, and states that macOS will confirm next (the handler is Void — the system dialog is the real gate, so there is no fake Cancel button).
- StepFun's rotated session is now persisted. `RefreshToken` rotates `Oasis-Token` on every call and the provider used the new header for that fetch only — the cached session aged out within the hour and every subsequent refresh 401'd until a manual re-import, despite settings claiming "自动续期". The rotated header is written back (guarded on it still containing `Oasis-Token`), and the static `lastResponse` variable the rotation used to read Set-Cookie from is gone in favor of returning the response from `rpc`.
- Browser imports can no longer report success for a signed-out browser. StepFun accepted any cookie on a matching domain (the console's session is `Oasis-Token`), LongCat accepted anything except `utm_*` (its SSO cookie is `passport_token_key`), and Nebula fell back to *all* cookies when no session-shaped one existed. All three now require their session cookie, and cached sessions are validated the same way — matching how SenseNova already behaved.
- Nebula's `New-Api-User` is bound to the profile the session cookie came from. The account id was read from the first profile that had one, so cookies from Profile 2 could be paired with the Default profile's account. The id is now read from the cookie's own profile, and an import that cannot read it fails with an actionable error instead of caching a session whose every request would 400.
- Imported cookie records are domain-boundary filtered. SweetCookieKit's default query match is `.contains`, so a lookup for `stepfun.com` also collected `not-stepfun.com` and `stepfun.com.evil.tld`; all six importers now keep only records whose domain equals an allowed domain or is a direct subdomain of it.
- Manually pasted cookies are normalized before use. A DevTools copy like `Cookie: session=abc; Path=/; HttpOnly` was sent verbatim, producing a pseudo-cookie literally named `Cookie: session`. A shared `CookieHeaderNormalizer` strips the header prefix and attribute entries, and the LongCat, StepFun and SenseNova manual paths now use it (OpenCode's already did).
- The credential file cache serializes read-modify-write. Concurrent provider completions could interleave `loadAll → mutate → write` and drop each other's keys, and all writers staged through one shared temp file name. Writes now hold a lock, stage through unique temp paths, and report whether they persisted; `CookieKeychainStore` returns the real outcome instead of claiming success after a failed Keychain write.
- DeepSeek's automatic browser session is cached at the disk level. The LevelDB scan ran on every refresh even when an API key was configured (the README says it happens only without credentials), and the 30-minute cache only covered network validation. The scan result is cached too, and a 401 now invalidates both caches so the next refresh rescans instead of retrying a dead token.
- `L10n.language` is lock-guarded. It was a `nonisolated(unsafe)` mutable property read from provider fetch paths that run off the main actor while the Settings picker writes it — a data race the compiler was told to ignore. Observation now goes through `objectWillChange` + the `languageDidChange` notification, which is what consumers already used.
- Hidden providers leave the expiry reminders. Reminders were computed from all eleven tabs regardless of visibility, so a hidden provider kept nagging from its frozen last-known quota, and tapping its reminder jumped to a tab that had no switcher button. Reminders now come from visible tabs only, hiding recomputes immediately, and a stale reminder tap opens the reminder settings pane instead of dead-ending.
- Reminder updates no longer republish an unchanged list (which rebuilt the whole open menu on every provider tick), and the summary-show toggle now triggers a menu rebuild like the other visibility switches.
- Support diagnostics no longer dump every response header: the gateway header dump filters cookie/authorization/token/api-key/secret headers before writing to `~/Library/Application Support/TokenBar/`. The StepFun and SenseNova settings-pane subtitles are localized instead of hard-coded Chinese.
- A refresh requested while a fetch is in flight is queued instead of dropped, and re-runs with the current settings when the in-flight fetch ends (previously a credential change during a slow request was lost until the next timer tick, and the old result was stamped with a fresh timestamp).
- Docs match the implementation again: `SECURITY.md` now documents the Keychain + 0600 file-cache storage of every credential (it previously claimed AK/SK were never persisted — the exact opposite of the code), the multi-provider cookie whitelists, the browser-import gates, the endpoint HTTPS policy and the truncated error summaries; both READMEs correct the SenseNova status (the endpoint works — it was still documented as "frozen"), the packaging signing behavior, the Ark probe cost, the LongCat selector semantics and the OpenCode cookie list; the 2026-09-04 audit report's status preamble is corrected to record what has since been fixed instead of claiming everything is still open.
- CI now gates the release path, not just tests: a second job runs `swift build -c release`, executes `Scripts/package_app.sh` end to end, and verifies the installed bundle's signature, architecture, provider-logo count and version — the gap that let a bundle with 8 of 11 logos ship with every test green. The workflow also sets `permissions`, cancel-in-progress concurrency and job timeouts, and fails early when the pinned toolchain is missing.
- Tests grew from 164 to 207 (13 new suites): the Ark probe order and its single billed fallback, error-summary truncation, Kimi account pairing, cookie normalization, the domain-boundary filter, the three import sign-in gates, the LongCat selector semantics, the menu-bar binding-constraint rules, the reminder no-republish behavior, and — for Alibaba Cloud — the ACS3 signature (pinned against the official CLI's algorithm with a fixed vector), the console-response decode for both plan kinds, and the mint-then-query fetch flow including plan detection, the Coding-Plan fallback, and the 401 / expired-envelope re-mint retries.
- Fixed the provider logos that `Scripts/package_app.sh` had been silently dropping. Replacing the resource-bundle `find | head -1` with a "deterministic" path made things worse, not better: it pinned `.build/arm64-apple-macosx/release/`, a leftover from an older SwiftPM scratch layout, while releases actually build into `.build/out/Products/Release/` (`.build/release` is a symlink to it). The stale copy passed an existence check with 8 of 11 logos, so StepFun, SenseNova and Aliyun rendered as blank in the installed app. The bundle is now resolved next to the binary that was just built and validated by **logo count** against `Sources/TokenBar/Resources` — the most complete candidate wins, and a bundle that cannot supply every logo aborts the install instead of shipping missing icons.
- The Ark tab no longer logs its success twice: the per-provider attempt line and a second summary line for the same fetch.
- `arkcli` subprocesses no longer inherit the whole parent environment (audit item F-04). Every provider reads its credential from the environment as a fallback, so launching TokenBar from a shell that had `DEEPSEEK_API_KEY`, `Z_AI_API_KEY`, `KIMI_CODE_API_KEY`, `GROKPOOL_PASSWORD`, `STEPFUN_API_KEY` or `ARK_API_KEY` exported handed all of them to a third-party node CLI — and to anything it execs. The subprocess now gets a fixed allowlist (`PATH` padded for homebrew, `HOME`, and `USER` / `LOGNAME` / `SHELL` / `TMPDIR` / `LANG` / `LC_ALL` when present), which is all the CLI needs: it keeps its own state in `~/.arkcli` and reads no provider environment variables. The Settings diagnostics `--version` call uses the same helper.
- Custom relay addresses now have to be safe to send credentials to (audit item F-01). APINebula sends its browser session cookie and GrokPool sends the administrator username and password to whatever URL Settings holds, and the only validation was stripping a trailing `/v1` and slashes — a mistyped `http://` meant credentials in cleartext. HTTPS is now required, with plain HTTP allowed only on loopback for self-hosted relays, and the policy lives in one shared `SecureEndpoint` so it cannot drift between providers. A configured-but-insecure address is reported as an error naming that address instead of silently falling back to the default host (which would have queried a different relay than the one you set).
- `Scripts/package_app.sh` now fails closed (audit item F-18). Signing failures used to fall back to an ad-hoc signature with `|| true`, the `codesign --verify` result was discarded, and the app was installed and had its quarantine attribute stripped regardless — a security failure reported as success, and an ad-hoc fallback is not free either: it changes the signature every build and silently revokes the Full Disk Access and browser-cookie Keychain grants the user approved. The selected identity is now used or the build stops; the bundle must verify before `/Applications` is touched; the installed copy is verified again and only then has quarantine cleared; and the certificate chain is printed. A missing `TokenBar_TokenBar.bundle` (provider logos) became an error instead of a warning, though the fixed path it resolved first turned out to be a stale build product — see the entry above.
- Typing in a settings text field no longer fires a refresh per keystroke. The three free-text fields bound straight to `AppSettings` (the APINebula and GrokPool base URLs and the OpenCode workspace id) each wrote UserDefaults and triggered that provider's refresh on **every character**; they are now debounced to 500 ms, so a completed edit costs one refresh instead of one per keystroke. Keychain-backed values were already safe because they only change when you press Save.
- Fixed the OpenCode Go tab failing with a bare `(400)` after opencode.ai redeployed. The workspace/org id came from calling a Next.js *server action* by its build hash, and that hash rotates with each deploy — once it started answering 500, the org id stayed `nil`, the status call went out unscoped, and the console's 400 looked like an unexplained API outage. The id now comes from the console's own cookie-authenticated `GET /console/api/orgs`, which is stable JSON. The resolution failure is also no longer swallowed by a `try?`, so a genuinely unresolvable workspace reports "set it manually in Settings" instead of a mystery 400.
- The shared `apiError` wording no longer names one provider. It read "方舟 API 错误 (%d)" / "Ark API error (%d)" while all 12 providers throw it, so OpenCode Go's failure blamed Ark in the menu; it is now "接口返回错误 (%d)" / "API error (%d)", with each provider's own detail after the status code.
- The OpenCode Go card header no longer reads like a link. It used the "打开 OpenCode Go" menu-action string as the provider identity, producing `打开 OpenCode Go · 认证: Chrome Profile 3`; the header now shows `OpenCode Go`.

- SenseNova (商汤) **Token Plan quota now works**, and the failure that hid it is fixed. The console's credit-pool meter `GET {origin}/lite/console/v1/tokenplan/pool-usage` answers only to the OAuth bearer token the console SPA uses (the plan API key is rejected with `Authentication type 'apikey' is not enabled`, and the session cookie alone gets `auth_header_missing`), so TokenBar now completes the same Hydra authorization-code + PKCE dance headlessly from the imported `oauth2_authentication_session` cookie — login and consent both auto-approve for this first-party client — and then keeps itself alive on the returned refresh token (access tokens last three hours), so the browser sign-in is needed once, not per refresh. Each credit pool renders its own rings (general + model-dedicated, 5-hour and weekly) instead of one averaged meter — and since two cards would otherwise carry the identical title, a plan card now spells out its edition when a snapshot holds several plans of the same product (`商汤 Token Plan · 通用积分池`), while single-plan providers keep the bare name and an edition that merely repeats the product (`Kimi For Coding`, `Go`) is never duplicated, wire numbers are accepted as strings or JSON numbers, and `nearest_grant_expiry` deliberately does not drive the expiry badge because it is a top-up grant's expiry, not the subscription's. Two stacked bugs caused the original blank tab: the session importer only required *some* cookie on `sensenova.cn` — whose domains also carry Baidu analytics (`Hm_lvt_*`) and GrowthBook (`gr_user_id`) cookies — so a logged-out import reported success and every request went out with junk credentials (import now requires `*authentication_session*` and invalidates older cached bags, logging cookie *names* only, never values); and the probe chain aborted on the first 401, so 6 of 7 candidates never ran. A working refresh is now a single request.
- Fixed StepFun (阶跃星辰) showing a bare `–` in the menu bar while its card right below showed percentages. The status-item number only accepted a session-rank window (`Session` / `5-hour` / balance / `24h`), and StepFun's credit-only Step Plan reports nothing but a monthly credit pool, so `menuBarWindow` resolved to `nil` and the text fell back to the dash. With no session-rank window the item now uses the tightest window — the same binding constraint the exhausted-pool rule already picks — so weekly/monthly-only plans (StepFun, and any Ark/Aliyun plan without a session meter) report a number. A plan that has a session window is unaffected, and an exhausted weekly/monthly pool still outranks everything. Side effect: those plans now also take part in the Overview's "tightest provider" icon pick, which previously skipped them.

- Fixed a sustained energy drain: the app idled at ~64% of one CPU core and added ~90 MB of RSS every refresh cycle (measured by `sample`-ing the running process — 44% of main-thread time in `-[NSStatusItem _updateReplicants…]`, 28% in the CoreAnimation commit that drew it). Two self-sustaining loops stacked up. The menu-bar icon was an `NSImage(drawingHandler:)` wrapping a brand SVG on a `wantsLayer` status button, so every CoreAnimation commit re-executed the handler, which re-dirtied the button, which made AppKit re-snapshot the status-item replicant — forever. Baking the icon once into static 1×/2× bitmap representations moved all rendering off the redraw path, and the layer-backed hover-zoom animation (the reason for `wantsLayer`) was dropped with it. That exposed a second loop: the replicant snapshot pass re-resolves the button's `effectiveAppearance` ~117 times a second, and the appearance observer rebuilt the icon on every emission; re-baking is now gated on the light/dark `bestMatch` actually changing, i.e. a real menu-bar theme switch. Result: **0.0% CPU at idle** and a flat RSS curve across refresh cycles. Icon inputs are also cached, so a rebuild needs an actual change in provider, mode, percent or rings.
- Collapsed the provider refresh layer: `UsageStore` carried eleven copies of the same `refreshX` / `runXProvider` / `finishXRefresh` trio plus three `switch`-per-tab accessors (33 `@Published` properties and 33 hand-written subscriptions). Every provider is now one row in a table-driven `Track` model (fetcher, availability gate, unavailable/error mapping, log wording) sharing a single refresh flow, and the state lives in one published `[ProviderTab: TrackState]` dictionary — ~990 lines removed with no change to refresh semantics (per-tab single-flight, stale-vs-error fallback, the OpenCode Go browser-session error mapping, and per-provider success logs are preserved). As a side effect, the old `MergeMany(…).dropFirst()` credential subscriptions let one initial value through per extra publisher and refreshed a tab at startup; each publisher now drops its own first value.
- Subscription/order expiry lookups are cached for 12 hours. The quota call needs the plan's end date from a second source (Ark's `ListSubscribeTrade`, also spawned as a second `arkcli` subprocess, and Z.ai's `subscription/list`), which previously ran on every refresh — but order end dates only move by whole days. One lookup per TTL instead of one per refresh, and Z.ai's cache key includes region + API key so switching either re-fetches at once. Still best-effort: a cold failure keeps the rings and drops the badge.

- Added the expiry dates the two oldest integrated subscriptions were missing, from their authoritative order APIs rather than a guess: **Volcengine Ark Coding/Agent Plan** now reads the signed OpenAPI action `ListSubscribeTrade` (`Result.InfoList[]` → `EndTime` of the `Status=Running` order, which is the console's 我的订阅 → 结束时间) on both the AK/SK path and the arkcli path (`arkcli api trade.list_subscribe` passthrough, so SSO-only users get it too), and **Z.ai Coding Plan** now reads `GET /api/biz/subscription/list` with the plan API key that already authenticates the quota endpoint (`status=VALID` → `nextRenewTime`, the console's 套餐概览 → 有效期至; falls back to the end of the order's `valid` range, and accepts `2026-10-18` / `2026年10月18日` / epoch spellings). Both feed the existing expiry badge and reminder engine, so no new UI. Team editions stay badge-free because their orders are seat-scoped. Every lookup is best-effort: a failure drops the badge, never the quota rings.
- Added a StepFun (阶跃星辰) Step Plan tab: the plan quota is console-session only (API keys get `api key not permitted` on all three RPCs; the gateway exposes no quota headers), so the provider imports the console cookies (Full Disk Access required) and drives the console's Connect-RPC service: `RefreshToken` rotates the session (the Set-Cookie rotation must replace Oasis-Token AND Oasis-Webid together), then `QueryStepPlanRateLimit` (5-hour / weekly / monthly-credit meters) and `GetStepPlanStatus` (plan name + `expired_at`) are queried with the Oasis-* headers. A window whose reset time is 0 does not apply to the plan (the Plus tier is credit-only) and is not shown as exhausted; such plans render a single monthly-credit ring plus the expiry badge.
- Added a SenseNova (商汤日日新) Token Plan tab (endpoint confirmation frozen): the console sign-in import works (OAuth2 `oauth2_authentication_session` cookie), and the quota structure is confirmed from the console page (dual credit pools — general + Flash-Lite — each with a weekly balance, a 5-hour window and a weekly quota). The data endpoint lives in a lazily-loaded chunk and awaits one logged-in capture; until then the provider probes candidate endpoints and writes every response to `~/Library/Application Support/TokenBar/sensenova-last-response.txt`.
- Browser-session import now tries every candidate browser in order (previously-used → source label → Chrome → other Chromium/Gecko → WebKit) and a Keychain denial on one candidate no longer aborts the rest. Chrome's TCC-protected profile directory makes store enumeration fail even when per-file reads work, so Chrome is always tried.
- Packaging signs with a stable identity when available (`TOKENBAR_SIGN_IDENTITY`, defaulting to an existing Apple Development identity): ad-hoc signing mints a new signature on every build, which invalidated the user's Full Disk Access and browser-cookie Keychain grants after each rebuild.
- The API-key gateway probe (`GET /v1/models` + response-header parsing) is shared by the StepFun and SenseNova providers; neither gateway publishes quota headers, so the console session is the authoritative source for both.
