# Changelog

All notable public changes to TokenBar are documented here.

## Unreleased

- Typing in a settings text field no longer fires a refresh per keystroke. The three free-text fields bound straight to `AppSettings` (the APINebula and GrokPool base URLs and the OpenCode workspace id) each wrote UserDefaults and triggered that provider's refresh on **every character**; they are now debounced to 500 ms, so a completed edit costs one refresh instead of one per keystroke. Keychain-backed values were already safe because they only change when you press Save.
- Fixed the OpenCode Go tab failing with a bare `(400)` after opencode.ai redeployed. The workspace/org id came from calling a Next.js *server action* by its build hash, and that hash rotates with each deploy — once it started answering 500, the org id stayed `nil`, the status call went out unscoped, and the console's 400 looked like an unexplained API outage. The id now comes from the console's own cookie-authenticated `GET /console/api/orgs`, which is stable JSON. The resolution failure is also no longer swallowed by a `try?`, so a genuinely unresolvable workspace reports "set it manually in Settings" instead of a mystery 400.
- The shared `apiError` wording no longer names one provider. It read "方舟 API 错误 (%d)" / "Ark API error (%d)" while all 12 providers throw it, so OpenCode Go's failure blamed Ark in the menu; it is now "接口返回错误 (%d)" / "API error (%d)", with each provider's own detail after the status code.
- The OpenCode Go card header no longer reads like a link. It used the "打开 OpenCode Go" menu-action string as the provider identity, producing `打开 OpenCode Go · 认证: Chrome Profile 3`; the header now shows `OpenCode Go`.

- SenseNova (商汤) **Token Plan quota now works**, and the failure that hid it is fixed. The console's credit-pool meter `GET {origin}/lite/console/v1/tokenplan/pool-usage` answers only to the OAuth bearer token the console SPA uses (the plan API key is rejected with `Authentication type 'apikey' is not enabled`, and the session cookie alone gets `auth_header_missing`), so TokenBar now completes the same Hydra authorization-code + PKCE dance headlessly from the imported `oauth2_authentication_session` cookie — login and consent both auto-approve for this first-party client — and then keeps itself alive on the returned refresh token (access tokens last three hours), so the browser sign-in is needed once, not per refresh. Each credit pool renders its own rings (general + model-dedicated, 5-hour and weekly) instead of one averaged meter — and since two cards would otherwise carry the identical title, a plan card now spells out its edition when a snapshot holds several plans of the same product (`商汤 Token Plan · 通用积分池`), while single-plan providers keep the bare name and an edition that merely repeats the product (`Kimi For Coding`, `Go`) is never duplicated, wire numbers are accepted as strings or JSON numbers, and `nearest_grant_expiry` deliberately does not drive the expiry badge because it is a top-up grant's expiry, not the subscription's. Two stacked bugs caused the original blank tab: the session importer only required *some* cookie on `sensenova.cn` — whose domains also carry Baidu analytics (`Hm_lvt_*`) and GrowthBook (`gr_user_id`) cookies — so a logged-out import reported success and every request went out with junk credentials (import now requires `*authentication_session*` and invalidates older cached bags, logging cookie *names* only, never values); and the probe chain aborted on the first 401, so 6 of 7 candidates never ran. A working refresh is now a single request.
- Fixed StepFun (阶跃星辰) showing a bare `–` in the menu bar while its card right below showed percentages. The status-item number only accepted a session-rank window (`Session` / `5-hour` / balance / `24h`), and StepFun's credit-only Step Plan reports nothing but a monthly credit pool, so `menuBarWindow` resolved to `nil` and the text fell back to the dash. With no session-rank window the item now uses the tightest window — the same binding constraint the exhausted-pool rule already picks — so weekly/monthly-only plans (StepFun, and any Ark/Aliyun plan without a session meter) report a number. A plan that has a session window is unaffected, and an exhausted weekly/monthly pool still outranks everything. Side effect: those plans now also take part in the Overview's "tightest provider" icon pick, which previously skipped them.

- Fixed a sustained energy drain: the app idled at ~64% of one CPU core and added ~90 MB of RSS every refresh cycle (measured by `sample`-ing the running process — 44% of main-thread time in `-[NSStatusItem _updateReplicants…]`, 28% in the CoreAnimation commit that drew it). Two self-sustaining loops stacked up. The menu-bar icon was an `NSImage(drawingHandler:)` wrapping a brand SVG on a `wantsLayer` status button, so every CoreAnimation commit re-executed the handler, which re-dirtied the button, which made AppKit re-snapshot the status-item replicant — forever. Baking the icon once into static 1×/2× bitmap representations moved all rendering off the redraw path, and the layer-backed hover-zoom animation (the reason for `wantsLayer`) was dropped with it. That exposed a second loop: the replicant snapshot pass re-resolves the button's `effectiveAppearance` ~117 times a second, and the appearance observer rebuilt the icon on every emission; re-baking is now gated on the light/dark `bestMatch` actually changing, i.e. a real menu-bar theme switch. Result: **0.0% CPU at idle** and a flat RSS curve across refresh cycles. Icon inputs are also cached, so a rebuild needs an actual change in provider, mode, percent or rings.
- Collapsed the provider refresh layer: `UsageStore` carried eleven copies of the same `refreshX` / `runXProvider` / `finishXRefresh` trio plus three `switch`-per-tab accessors (33 `@Published` properties and 33 hand-written subscriptions). Every provider is now one row in a table-driven `Track` model (fetcher, availability gate, unavailable/error mapping, log wording) sharing a single refresh flow, and the state lives in one published `[ProviderTab: TrackState]` dictionary — ~990 lines removed with no change to refresh semantics (per-tab single-flight, stale-vs-error fallback, the OpenCode Go browser-session error mapping, and per-provider success logs are preserved). As a side effect, the old `MergeMany(…).dropFirst()` credential subscriptions let one initial value through per extra publisher and refreshed a tab at startup; each publisher now drops its own first value.
- Subscription/order expiry lookups are cached for 12 hours. The quota call needs the plan's end date from a second source (Ark's `ListSubscribeTrade`, also spawned as a second `arkcli` subprocess, and Z.ai's `subscription/list`), which previously ran on every refresh — but order end dates only move by whole days. One lookup per TTL instead of one per refresh, and Z.ai's cache key includes region + API key so switching either re-fetches at once. Still best-effort: a cold failure keeps the rings and drops the badge.

- Added the expiry dates the two oldest integrated subscriptions were missing, from their authoritative order APIs rather than a guess: **Volcengine Ark Coding/Agent Plan** now reads the signed OpenAPI action `ListSubscribeTrade` (`Result.InfoList[]` → `EndTime` of the `Status=Running` order, which is the console's 我的订阅 → 结束时间) on both the AK/SK path and the arkcli path (`arkcli api trade.list_subscribe` passthrough, so SSO-only users get it too), and **Z.ai Coding Plan** now reads `GET /api/biz/subscription/list` with the plan API key that already authenticates the quota endpoint (`status=VALID` → `nextRenewTime`, the console's 套餐概览 → 有效期至; falls back to the end of the order's `valid` range, and accepts `2026-10-18` / `2026年10月18日` / epoch spellings). Both feed the existing expiry badge and reminder engine, so no new UI. Team editions stay badge-free because their orders are seat-scoped. Every lookup is best-effort: a failure drops the badge, never the quota rings.
- Added a StepFun (阶跃星辰) Step Plan tab: the plan quota is console-session only (API keys get `api key not permitted` on all three RPCs; the gateway exposes no quota headers), so the provider imports the console cookies (Full Disk Access required) and drives the console's Connect-RPC service: `RefreshToken` rotates the session (the Set-Cookie rotation must replace Oasis-Token AND Oasis-Webid together), then `QueryStepPlanRateLimit` (5-hour / weekly / monthly-credit meters) and `GetStepPlanStatus` (plan name + `expired_at`) are queried with the Oasis-* headers. A window whose reset time is 0 does not apply to the plan (the Plus tier is credit-only) and is not shown as exhausted; such plans render a single monthly-credit ring plus the expiry badge.
- Added a SenseNova (商汤日日新) Token Plan tab (endpoint confirmation frozen): the console sign-in import works (OAuth2 `oauth2_authentication_session` cookie), and the quota structure is confirmed from the console page (dual credit pools — general + Flash-Lite — each with a weekly balance, a 5-hour window and a weekly quota). The data endpoint lives in a lazily-loaded chunk and awaits one logged-in capture; until then the provider probes candidate endpoints and writes every response to `~/Library/Application Support/TokenBar/sensenova-last-response.txt`.
- Browser-session import now tries every candidate browser in order (previously-used → source label → Chrome → other Chromium/Gecko → WebKit) and a Keychain denial on one candidate no longer aborts the rest. Chrome's TCC-protected profile directory makes store enumeration fail even when per-file reads work, so Chrome is always tried.
- Packaging signs with a stable identity when available (`TOKENBAR_SIGN_IDENTITY`, defaulting to an existing Apple Development identity): ad-hoc signing mints a new signature on every build, which invalidated the user's Full Disk Access and browser-cookie Keychain grants after each rebuild.
- The API-key gateway probe (`GET /v1/models` + response-header parsing) is shared by the StepFun and SenseNova providers; neither gateway publishes quota headers, so the console session is the authoritative source for both.

- Added a StepFun (阶跃星辰) Step Plan tab: the console quota is not on the public gateway (only `GET /v1/accounts` balance is public; credit/usage endpoints return 404), so the provider imports the console browser session (cookie-based, `platform.stepfun.com`; Full Disk Access required on current macOS) and reads the console's Connect-RPC service `step.openapi.devcenter.Dashboard/GetStepPlanStatus` — fiveHour / weekly / credit meters and `expireTime` map to the rings, the expiry badge, and the expiry reminders. Browsers that hold the sign-in are preferred over Safari (whose cookie file needs Full Disk Access and is a last resort).
- Added a SenseNova (商汤日日新) Token Plan tab (stage 1 — endpoint confirmation): the plan page documents no quota API (gateway routes are model-only), so the provider imports the console sign-in and probes the candidate endpoints, writing every response to `~/Library/Application Support/TokenBar/sensenova-last-response.txt`; the first authenticated capture fixes the parser. Free beta: 60,000 credits / 5 hours.

- The Kimi tab now shows the membership expiry: the shared-pool `GetSubscriptionStats` response already carried an `expireTime` that was decoded but never surfaced; it now feeds the plan-expiry badge and the expiry reminders (same treatment as OpenCode Go).

- Migrated the OpenCode Go tab to the console JSON API: opencode.ai replaced the server-rendered workspace page (now an empty SPA shell) with a new console app. The provider now reads `GET /console/api/go/status` (authenticated by the new `console_session` browser cookie, scoped with `x-org-id`), mapping the `fiveHour`/`week`/`month` micro-cent meters onto the session/weekly/monthly rings and `access.endsAt` onto the plan-expiry badge and expiry reminders. The browser-session import now also captures the `console_session` cookie alongside the legacy `auth` cookie, prefers readable Chromium/Gecko browsers over Safari (whose cookie file needs Full Disk Access), and — when Chrome is installed but its cookie store is unreadable — tells the user to grant TokenBar Full Disk Access instead of reporting "no session found". A support diagnostic (`~/Library/Application Support/TokenBar/opencode-last-response.txt`) records browser discovery and response heads (names only, never cookie values).

- Fixed the blank "TokenBar Settings" window that appeared whenever a running instance was reopened (double-click, Spotlight/Raycast, `open`): macOS opens the SwiftUI `Settings` scene itself in that path, before any delegate callback, and the scene's `EmptyView` placeholder rendered as an empty window. The scene now hosts the real settings UI (and is the app's only settings window — the parallel AppKit window controller is gone), so every entry point (menu, ⌘,, reopen) shows the same window. The `applicationShouldHandleReopen` delegate focuses it instead of spawning a placeholder.
- Polished the settings window: panes now open with an icon bubble + title + one-line subtitle header, the sidebar brand block is smaller and tighter, and manual-subscription rows render as bordered cards with a per-row delete button.
- Added a subscription **expiry-reminder** feature: a "订阅到期 / Expiring subscriptions" section at the top of the Overview menu lists every integrated plan with a verified expiry date (OpenCode Go renewal, LongCat pack expiry, etc.) plus user-managed manual entries, each with a color-coded countdown and remaining-quota percent. The reminder rule nags only when a plan expires within the configurable lead time (3/7/14/30 days, default 7) and still holds ≥50% quota, so nearly exhausted plans stay quiet. Optional macOS notifications de-duplicate to one per subscription per day (notifications only appear in the packaged app; source runs keep the in-menu section). Manual subscriptions (name + expiry date + note, with a per-row delete button) cover services TokenBar does not integrate and are edited in the new **Settings → 订阅提醒** pane; rows keep local draft state while typing so edits are never swallowed by re-renders.
- Added an Alibaba Cloud (阿里云百炼) **Coding Plan** tab (stage 1): the dedicated `sk-sp-…` API key is entered in **Settings → 阿里云 Coding Plan** (stored in Keychain + file cache, with an `ALIYUN_CODING_PLAN_API_KEY` environment fallback), quota windows map onto the canonical session/weekly/monthly rings (the Pro plan's 5-hour 6,000 / weekly 45,000 / monthly 90,000 request windows), and the card reuses the plan-card expiry badge. Alibaba documents no public quota API, so until the plan is activated the provider validates the key and then reports an honest "not activated yet" state; the stage-2 endpoint adaptation is prepared in `docs/aliyun-handoff.md`.

- Replaced the menu-bar capsule meter with the concentric ring gauge shared with the plan cards: three-window plans show monthly (outer) / weekly (middle) / session (inner) rings, while single-window balance providers (DeepSeek, Nebula, GrokPool, LongCat) collapse to one balance-toned ring; empty state draws faint placeholder tracks in the same shape. The old meter modes are renamed to Rings / Rings + percent / Logo + rings (stored `logoAndBar` migrates automatically), the gauge is full-colour so the hues match the cards (re-rendered on theme change), and the Dock/Finder `AppIcon` is now a blue rounded square with the same three rings instead of the white capsule.
- Added an Access Key / Secret Key credential entry to the Ark settings pane (stored in Keychain + file cache), taking precedence over environment variables and then the arkcli SSO session. Volcengine IAM long-lived keys never expire, so entering a read-only sub-account key pair once removes the periodic `arkcli auth login volc-sso` re-login loop that SSO refresh chains (~48 h rotating refresh token) otherwise require. The signed OpenAPI path only reports Coding Plan quota, so arkcli stays available as the AgentPlan/team-seat source.
- Reworked the menu-bar percentage into a binding-constraint metric ported from CodexBar's combined display rule: it still shows the Session/5-hour remaining by default, but when a longer-cadence window (weekly/monthly) is fully exhausted it shows that zeroed window instead. Previously a spent weekly pool alongside a freshly reset 100% session ring read as "100%" while every request was actually blocked.
- The Zhipu provider icon now uses `fill="currentColor"` like the other monochrome brand SVGs instead of a hard-coded white fill; template rendering inside TokenBar is unchanged, but hosts that draw the raw SVG without template treatment no longer render it invisible-on-light.

- Added a LongCat (longcat.chat) tab: the usage endpoints live behind the longcat.chat console (not api.longcat.chat) and authenticate with a browser sign-in session. The provider reads the active token pack from the pay metering service (`POST /api/pay/quota/metering/token-packs/summary`, `data.currentLot`: `totalToken` / `consumedToken` / `remainingToken` / `expireTime`); the remaining-quota ring = remaining-token share. The card shows total / used / remaining with percents, plus an optional fuel-pack balance and nearest-expiry countdown. Browser-session import supports a multi-browser fallback (Chrome / Arc / Safari / Edge / Brave / Firefox) and falls back to a manually pasted Cookie header or `LONGCAT_MANUAL_COOKIE`. Credentials are stored in Keychain + file cache; only `utm_` tracking cookies are dropped, the rest of the `longcat.chat` session cookies are forwarded.

- Migrated the GrokPool tab to the grok2api admin API: the grok-farm gateway left the new-api console API (`api/user/self` / `api/log/self`), so the provider now signs in with the Grok2API console administrator username and password (`POST /api/admin/v1/auth/login`, stored in Keychain + file cache with `GROKPOOL_USERNAME` / `GROKPOOL_PASSWORD` fallbacks), caches the short-lived Bearer token in memory (re-login on 401 or after the ~15-minute expiry), and reads the 24-hour dashboard (`GET /api/admin/v1/dashboard?period=24h`): request counts and success rate (ring), billed cost (10^10 ticks = $1), input/cached/output/reasoning token split, active accounts, and the top model. The settings pane's menu-bar choice now toggles between the success percent and the 24h cost (`$`).

- DeepSeek and APINebula now have a per-provider "Menu bar shows" setting (remaining percent vs money balance). In balance mode the status item shows the remaining balance with the correct currency symbol—`¥` for CNY or `$` for USD on DeepSeek (following the wallet currency returned by the API), always `¥` on APINebula—formatted to two decimals, and widens automatically to fit. The Overview summary rows follow the same choice.
- Fixed the Kimi For Coding monthly/shared-pool ring not appearing: the Kimi access token expires in 15 minutes but the app never refreshed it, so the `www.kimi.com` console calls 401'd and the outer ring silently vanished. The app now collects the 90-day refresh token, refreshes expired access tokens via `/api/auth/token/refresh` (rotating the refresh token), retries 401s once, and falls back to a raw-byte LevelDB scan for newer Kimi.app builds whose structured `readEntries` returns empty.
- Fixed multiple admin/Keychain password prompts on startup. `CookieKeychainStore` now skips `SecItemUpdate` when the value is unchanged, and credential resolution uses the still-valid cached access token instead of swapping it on every refresh; combined with the file-cache-first read path, warm restarts no longer touch the Keychain.
- Added a Kimi For Coding tab: membership quota from `api.kimi.com/coding/v1/usages` (weekly quota + 5-hour rate-limit window, mapped to the weekly and session rings), with an API key stored in Keychain + file cache (or the `KIMI_CODE_API_KEY` environment fallback). Importing the `www.kimi.com` browser sign-in additionally reads `GetSubscriptionStats` and maps the **shared Kimi Code + Kimi Work pool** to the monthly ring (the two products bill against one shared pool).
- Added a Z.ai (Zhipu GLM) Coding Plan tab: quota windows from `api/monitor/usage/quota/limit` (5-hour session + weekly rings, plus a monthly MCP time window on some plans), with Global / BigModel CN region selection and an API key stored in Keychain + file cache (or the `Z_AI_API_KEY` environment fallback).
- `CREDIT_LIMIT` windows (the type newer BigModel CN plans return instead of `TOKENS_LIMIT`) are treated as token/credit windows and drive the 5-hour and weekly rings; the plan tier is read from the response's `level` field.
- Added a multi-provider **Overview** tab that lists every visible provider with remaining percent and a teal→blue capsule meter; click a row to open that provider's full card. Toggle it in **Settings → General**.
- Status-item logo glyphs are 16×16pt and percent text uses the system font size, matching CodexBar's menu-bar scale.
- Credentials are mirrored to a local file cache (`~/Library/Application Support/TokenBar/credentials.json`, mode 0600) so warm restarts never need Keychain UI; Keychain remains the canonical store and backfills the file on first silent read.
- Added an APINebula (new-api relay) tab with a balance ring (cumulative spend vs spend + balance), today/monthly cost, token counts, request counts, and a cache-read/uncached/output split aggregated from the console usage log.
- APINebula balance/usage endpoints are console APIs: credentials come from the browser sign-in session (imported explicitly and cached locally) or an optional API key/environment fallback.
- Added a DeepSeek tab with balance, today/monthly cost, token counts, request counts, and a cache hit/miss/output breakdown, mirroring CodexBar's DeepSeek monitoring.
- Added a single balance ring for DeepSeek (this month's spend vs spend + balance) that recalculates automatically after a top-up.
- Added DeepSeek credential entry in Settings (API Key / Platform Token, stored in Keychain + file cache) and silent auto-resolution of the signed-in DeepSeek Platform session from Chrome local storage when no key is configured.
- Added per-provider show/hide toggles in each provider's settings pane; hidden providers leave the switcher and stop background refresh.
- Added CodexBar-style menu-bar display modes: meter bar, bar + percent, percent only, logo only, logo + percent, and logo + bar, with provider brand icons (doubao/opencode/deepseek/apinebula) shipped as resources.
- Provider brand logos now also appear in the settings sidebar and menu switcher buttons.
- Browser-session import (OpenCode / APINebula) is an explicit settings action only; background/startup refreshes never decrypt browser cookie stores or prompt for Keychain passwords.
- Added an OpenCode Go tab backed by authoritative subscription-page data, with explicit browser-session import or a manual Keychain-stored Cookie.
- Isolated Ark and OpenCode refresh, error, stale-data, and last-updated state so one provider cannot overwrite the other.
- Prevented background and ordinary refreshes from repeatedly reading browser cookie stores or triggering recurring Keychain password prompts.
- Kept one persistent menu attached to the status item, eliminating the first-click miss and allowing tab switches and refresh state to update in place.
- Kept the menu-bar percentage synchronized with the selected provider's Session value while using a fixed-width anchor to avoid horizontal movement.
- Reworked the settings window into compact General, Ark, OpenCode Go, and Diagnostics panes.
- Refined the remaining-quota rings with distinct color families, a wider neutral track, contained progress strokes, and a clean full-ring state at 100%.
- Added a persisted switch for refreshing when the menu-bar item opens; the default remains interval-only refresh.
- Coalesced overlapping refresh triggers and scheduled the timer in common RunLoop modes to keep refreshes stable while the menu is open.
- Fixed the status-item hover selector crash, kept Refresh inside the open menu, and made the primary ring/centre consistently represent remaining quota.
